# Hive audit: moved workspace and Roblox sign-in — 2026-11-05

- The copied workspace had no `.git` directory; its existing source files matched `origin/main` after restoring the Git index. The original icon files remain in the workspace; copies are embedded in the application and setup.
- Roblox delivered the earlier login form during inspection, while the reported screenshot shows a newer variant. Both are supported by explicit username/password selectors and visible `Log In` / `Sign in` buttons. The newer DOM is covered by a local fixture, not a verified real authenticated session. Website challenges remain interactive, and a real successful account login has not been tested.
- The old consent button ID was absent in one observed page; an exact-text `Accept All` fallback is restricted to the Roblox page. This may change with localization or Roblox redesign.
- Browser startup previously serialized the opening of every Chromium instance. Once an executable has been verified, separate browser launches can proceed concurrently; first-time discovery/download remains serialized. One process per account is retained for isolation; this has a memory cost, and no browser performance benchmark was collected.
- Current-user MCP access is a named pipe. The Codex global registration was removed on request; processes in the same Windows account can access the local pipe while Hive is open. There is no phone/internet service or remote backend.
- Copy operations decrypt a requested value only when invoked. Passwords and `.ROBLOSECURITY` copied to the Windows clipboard can be read by applications with clipboard access and remain there until replaced. Account data and secrets are not logged by these actions.
- NuGet reported no known vulnerable direct or transitive packages from the configured source at audit time. All direct packages report current stable versions. PuppeteerSharp 25.15.0 remained current in the checked feed; plugin sources are vendored and were not automatically replaced.
- Complete RAM feature parity, real multi-client/private-server game tests, privacy/security penetration testing, robust disconnect detection and true external FPS control remain open. An explicit presence check was added and the endpoint was checked with a public Roblox user ID; response privacy and availability remain controlled by Roblox. Session API and ticket workflows still depend on Roblox endpoints which can change.

Roblox documents Open Cloud as a separate authorization system and warns that legacy cookie APIs can change without notice: https://create.roblox.com/docs/cloud . The OAuth flow is not a drop-in replacement for a game client session: https://create.roblox.com/docs/cloud/auth/oauth2-overview .
